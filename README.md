# 과제 12: 퀵 정렬의 피벗 선택에 따른 성능 비교 및 분석

본 문서는 C 언어로 구현한 퀵 정렬(Quick Sort) 알고리즘에서 **피벗(Pivot) 선택 방법**에 따른 숫자 비교 횟수 성능 차이와, **재귀적(Recursive) 및 반복적(Iterative) 구현 방식**의 실행 시간 비교 결과를 분석한 보고서입니다.

---

## 1. 실험 결과 개요
데이터 크기($n$)를 1,000부터 20,000까지 2배씩 증가시키며 세 가지 피벗 선택 방법(`First`, `Random`, `Median-of-Three`)의 비교 횟수를 측정하였습니다.

- **First Element (첫 번째 원소)**: 배열의 초기 상태에 크게 의존합니다. 입력 데이터가 우연히 편향되거나 정렬되어 있을 경우 최악의 분할($O(n^2)$)에 가까워져 비교 횟수가 급증할 위험이 있습니다.
- **Random Pivot (무작위 원소)**: 특정 입력 패턴에 취약한 점을 보완하여 평균적으로 안정적인 분할 비율을 유지합니다.
- **Median-of-Three (세 원소의 중앙값)**: 첫 번째, 중간, 마지막 원소 중 크기 순으로 중간값을 피벗으로 삼기 때문에 분할의 균형성이 매우 뛰어납니다. 전반적으로 가장 적고 효율적인 비교 횟수를 기록합니다.

---

## 2. 피벗 선택 방법별 성능 차이 원인 분석

1. **분할 균형성 (Balance of Partitioning)**
   - 퀵 정렬의 핵심 성능 지표는 분할된 두 서브 배열의 크기가 얼마나 균등한가에 달려 있습니다. 균등하게 나뉠수록 재귀 트리의 깊이가 $O(\log n)$으로 줄어듭니다.
   - `First` 방법은 무작위 데이터라 하더라도 중앙값과 거리가 먼 값이 피벗으로 선택될 확률이 존재하여 불균형한 파티션을 자주 유발합니다.
   - 반면 `Median-of-Three`는 극단적인 최솟값이나 최댓값이 피벗으로 선택되는 것을 원천적으로 차단하므로, 재귀 깊이를 최소화하여 전체 비교 횟수를 크게 절감합니다.

2. **추가 연산 비용의 상쇄 효과**
   - `Median-of-Three`는 피벗을 확정하기 위해 시작, 중간, 끝 원소 간의 대소 비교(최대 3회)를 선행합니다.
   - 이로 인해 미세한 추가 비교가 발생하지만, 이 비교 비용보다 **균형 잡힌 분할을 통해 전체 정렬 과정에서 절약되는 막대한 비교·교환 횟수**의 이점이 훨씬 크기 때문에 성능 면에서 가장 우수한 결과를 보여줍니다.

---

## 3. [보너스] 재귀적 퀵 정렬 vs 반복적 퀵 정렬 실행 시간 비교

- **실험 조건**: Data Size = 10,000, Pivot = Median-of-Three, 50회 반복 측정 평균
- **측정 결과 예시**:
  - Recursive Quick Sort : 약 0.72 ms
  - Iterative Quick Sort : 약 1.15 ms

### 💡 실행 시간 차이 원인 분석
1. **함수 콜 스택(Call Stack) 오버헤드 vs 명시적 스택 관리 비용**
   - **재귀적 방법**은 시스템 하드웨어 및 컴파일러가 최적화한 콜 스택을 이용하므로 함수 호출/복귀 메커니즘이 매우 빠릅니다.
   - **반복적 방법**은 동적 메모리 할당을 통한 명시적 배열 스택(`stack`)을 생성하고, 매 분할 단계마다 인덱스를 `push`/`pop`하는 연산 코드가 수동으로 수행됩니다. 이 인덱스 관리 부하로 인해 알고리즘의 이론적 복잡도는 같아도 실제 실행 시간은 소폭 증가할 수 있습니다.
2. **지역성(Locality)과 메모리 효율**
   - 재귀 호출은 CPU 레지스터와 하드웨어 캐시의 활용도가 높은 반면, 별도의 스택 배열을 조작하는 반복 방식은 미세한 메모리 접근 오버헤드가 더해지게 됩니다.
